= tree-sitter-asciidoc

This is Asciidoc parser (early WIP) for `nvim-treesitter`.

Original Asciidoc parser and converter (_Asciidoctor_) is written in Ruby.
Antora uses _Asciidoctor.js_ (Ruby transpiled to JS).

This parser is designed as a writers tool, so it's syntax highlighting would
help you see if you made an error. This includes parsing option block
parameters (table `cols=` for example) to help you write them correctly, or
disabling highlights for literal blocks to indicate there would be no parsing
inside. Parser "knows" what parameters are valid for xrefs, includes or icon
macros, so it would highlight known ones. On the other side, it can understand
whether syntax of non-Asciidoctor parameters (`[parameter="value;value"]`) is
correct or not.

Neovim highlights code in `[source,LANG]` blocks with the language parser of
`LANG`. See <<Code block highlighting>>.

I use Antora, so this parser supports Antora resource locator strings
(`+include::v1@Component:module:page$index.adoc[]+`).

== Installation

I've moved to `main` branch of
`link:https://github.com/nvim-treesitter/nvim-treesitter[nvim-treesitter]`,
so installation of this parser does not require
link:https://github.com/cpkio/nvim-treesitter-asciidoc[additional repo],
which was required before.

.Activate custom parser for `main` branch of `nvim-treesitter`
====
[source,lua]
----
vim.api.nvim_create_autocmd('User', {
    pattern = 'TSUpdate',
    callback = function()
        require("nvim-treesitter.parsers").asciidoc = {
          install_info = {
            url = "https://github.com/cpkio/tree-sitter-asciidoc",
            revision = "0adab3201e5fc85cc2eb1d5772a976da27689422",
            queries = 'queries'
          },
          tier = 2
        }
    end,
  })
----
====

.Parser installation
....
:TSInstall asciidoc
....

== Code block highlighting

The file `queries/injections.scm` tells Neovim which text in a source block
is code in a different language. Neovim sends this text to the language parser
of `LANG` and highlights it with that parser.

Supported syntax:

- `[source,LANG]` above a `----` listing block;

- `[source,LANG]` above a `....` literal block;

- a block title (`.Title`) above or below the `[source,LANG]` line;

- more attributes after `LANG` (`[source,ruby,linenums]`).

A source block can be at the top level or after a list continuation (`+`).
It can also be in a different block, such as an example block (`====`) or a
table cell.

....
[source,json]    <- block_type "source", attribute "json"
.Optional title
----             <- block_listing: Neovim sends its text to the json parser
{"a": 1}
----
....

Install the language parser for each `LANG` that you use. Without the
language parser, Neovim shows the block as plain text and gives no error.

....
:TSInstall json
....

Neovim changes `LANG` to lower case and changes `-` to `_`. Then Neovim looks
for a language parser or a filetype with that name. `nvim-treesitter` already
knows names such as `js`, `py`, `ts` and `sh`. For a different name, add an
alias in your `init.lua`:

[source,lua]
----
vim.treesitter.language.register('bash', { 'console', 'shell', 'shell_session' })
vim.treesitter.language.register('yaml', 'yml')
vim.treesitter.language.register('ruby', 'rb')
vim.treesitter.language.register('rust', 'rs')
----

Known limitations:

- The AsciiDoc parser gives an `ERROR` node for `[,LANG]` and
  `[source%linenums,LANG]`.

- The AsciiDoc parser does not close the attribute line `[source,c++]`. Then
  `++` starts an inline passthrough that continues to the end of the document.

- `queries/injections.scm` does not use the `:source-language:` attribute.
  A `[source]` block without `LANG` gets no highlighting.

- `[source,LANG]` on a `--` open block or on a paragraph gives no
  highlighting.

- Neovim does not send callouts, `include::` lines and `//` comment lines in
  the block to the language parser.

- The tests used only Neovim with `nvim-treesitter` (`main` branch).

== Parsing compications

I didn't inspect Asciidoctor code, but it seems Asciidoctor parses documents
in reverse, from last line to first. This would make it quite easy to parse
certain Asciidoc expressions. `tree-sitter` cannot parse document from back to
front, so we have to use some tricks.

`tree-sitter-asciidoc` uses external parser code to detect distinct Asciidoc
expressions, which are called *markers*. When a marker is detected, external
parser returns a token, and then `tree-sitter` does the heavy lifting of
switching states.
